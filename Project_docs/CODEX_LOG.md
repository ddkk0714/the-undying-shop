# Codex 활용 기록

## 우리의 방법론 — 문서 → 모듈 → 검증 루프

우리는 화면과 게임 규칙을 분리하고, 먼저 모듈 문서·공유 타입·수용 기준을 확정했다. Codex는 Phaser를 모르는 순수 TypeScript 코어와 콘텐츠 데이터만 담당했고, Claude Code는 그 상태를 읽어 화면을 만들었다. 모든 규칙 변경은 시드 RNG와 헤드리스 시뮬레이터로 재현했으며, 화면에서 발견된 문제도 테스트로 고정한 뒤 수정했다. 이는 AI에게 구현을 일괄 위임한 방식이 아니라, 사람이 모듈·소유권·검증 경계를 설계한 분업 구조다.

## D0 · 콘텐츠 계약

**프롬프트**: M03/M05/M06/M07/M10/M11 명세를 실행 가능한 JSON 데이터로 옮긴다.
**산출**: 밸런스, 아이템 12종, 스타 5명, 페르소나, 갈림길, 무전·채팅·서사 콘텐츠.
**수정한 것**: 표의 수치·수량·UTF-8을 먼저 검증해 코어와 화면이 같은 데이터를 읽게 했다.
**배운 것**: 데이터 계약을 먼저 고정하면 규칙과 UI가 서로 다른 수치를 해석하는 문제를 막을 수 있다.

## D1 · M02 상태머신과 M03/M04/M05 로스터·경제

**프롬프트**: 동결된 계약 위에 8일 상태머신, 소생·폐기, 계약 방문자, 페르소나 승계를 구현한다.
**산출**: 순수 reducer/store/RNG/sim, 소생 견적, 유품, 계약 수락·거절, 진열·물약·초기 재고.
**수정한 것**: 시체·몸·페르소나를 분리하고, 계약 지원자는 수락 뒤에만 출연·승계할 수 있게 했다. 골드 부족·지원자 고갈의 조기 종료 안전망도 추가했다.
**배운 것**: 계약 파일 변경은 CCR로 분리하고, 시체·정산처럼 여러 경로가 만나는 규칙은 하나의 멱등 함수로 합쳐야 이중 지급을 피할 수 있다.

## D2 · M06 하강·전투·무전

**프롬프트**: 3층 주기 전투, 시드 갈림길, 목격, 강제 사망을 화면 없이 완결한다.
**산출**: 장비 기반 HP/ATK/DEF 전투, 공격·방어·어필, 지체 페널티, 18/23/28F 목격, 거짓말 콜백.
**수정한 것**: 같은 시드에서는 같은 갈림길 결과가 나고 좌우 표시는 시드에 따라 바뀌게 했다. 사망 시 Corpse·팬·골드·최고층을 한 번만 정산하며 전투 대사와 하강 한계 사인도 한국어로 통일했다.
**배운 것**: RNG를 함수 내부의 숨은 난수가 아니라 입력·cursor 소비로 만들면 확률 규칙도 테스트 가능한 결정론이 된다.

## D3 · M08/M09/M11 정산·검시·엔딩

**프롬프트**: 죽음 뒤의 4가지 발표 조합과 기록·엔딩 규칙을 상태 전이로 증명한다.
**산출**: 얕은 사망 팬 손실, 일일 수입 원장, 검시 훼손 유품, HIDDEN 전이, A/B 엔딩 판정.
**수정한 것**: 온전한 시체를 실패로 공표하면 스타가 캐스팅에서 빠지고, 훼손하면 목격 기록이 억제되도록 분리했다.
**배운 것**: ‘진실’과 ‘발표’를 별도 상태로 저장해야 거짓 공표의 비용을 정확히 표현할 수 있다.

## D4 · M07 채팅·슈퍼챗과 M03 열화

**프롬프트**: 시청자 반응을 실제 방송 상황과 연결하고, 되살아난 몸의 후유증을 반영한다.
**산출**: leak·삭제 역풍·payPool, 상황별 채팅/슈퍼챗, 방송 시청자·채팅 속도 모델, 열화·승계 규칙.
**수정한 것**: 초반은 조용하고 깊이·위험·어필·슈퍼챗에 따라 시청자와 채팅 밀도가 변한다. 슈퍼챗은 감정·대사 payload를 전달하며, 진실 채팅은 과잉 삭제해도 사라지지 않는다.
**배운 것**: 화면 효과가 필요한 규칙도 core에서는 작은 의미 신호(payload)만 만들면 렌더러와 충돌하지 않는다.

## D5 · M10 슈퍼챗 중심 경제 검증

**프롬프트**: 현실적인 수입 구조를 시뮬레이션으로 검증하고, 무리한 밸런스 변경은 되돌린다.
**산출**: 보수·적극 계약, 저어필·항상어필, 훼손 회복 정책과 1,000시드 검증.
**수정한 것**: 슈퍼챗을 변동성 높은 주수입(약 61%), 굿즈를 안정 수입(약 36%), 재고/유품 판매를 비상 수단(약 4%)으로 확정했다. 목표에 맞지 않은 단일 노브 실험은 저장소에 남기지 않았다.
**배운 것**: 밸런스 목표와 자동 플레이 정책이 다르면 숫자를 억지로 맞추지 말고, 정책 자체가 어떤 플레이를 대표하는지 먼저 검증해야 한다.

## D6 · CCR-004 방송 멘탈

**프롬프트**: 큰 피해·기괴한 적·목격 연출에 따라 용사별로 다른 멘탈 감소를 만든다.
**산출**: 방송 단위 멘탈, grit 기반 공포 내성, 특수 적/목격/피해 규칙, 공포 무전 대사.
**수정한 것**: 수치와 임계값을 콘텐츠 데이터로 분리했고, 0이어도 즉사시키지 않으며 공포 대사만 강해지게 했다.
**배운 것**: 시각 연출을 위한 상태라도 코어에서 먼저 결정적으로 갱신하면 화면은 안전하게 그 값만 표현하면 된다.

## D6 · M05 용사 3슬롯 장비 전달

**프롬프트**: 상점에서 출연자에게 무기 1개, 방어구 1개, 기타 1개를 건네고 방송 중 사용하게 한다.
**산출**: 무기·방어구·기타 슬롯을 데이터로 고정하고, 시작 장비 4종과 장착·소비 규칙을 headless 테스트로 검증했다.
**수정한 것**: `balance.equipment.slotByItem`이 각 장비의 슬롯을 정한다. 잘못된 슬롯 장착은 무시되고, 장착된 물약만 방송 중 사용할 수 있으며 사용 후 기타 슬롯과 인벤토리에서 함께 사라진다. 자동 시뮬 정책도 슬롯 규칙을 따른다. CCR-005의 방문 계약 흥정은 계약서별 하루 1회만 `haggleFeeMultiplier`를 적용하며, 수락하면 할인된 금액을 즉시 차감한다.
**배운 것**: 장비 종류를 타입 계약에 억지로 추가하지 않고 콘텐츠 매핑으로 정하면, 화면 계약을 넓히지 않으면서도 장비와 소모품을 동일한 3칸 흐름으로 검증할 수 있다.

## D7 · 편성실 대사 모션

**프롬프트**: 편성실 손님 대사를 글자 단위로 출력하고, 완료 뒤 작은 세모가 통통 뛰며, 말하는 동안 캐릭터 대사·표정 스프라이트가 바뀌게 한다.
**산출**: 재사용 가능한 `Dialogue` 컴포넌트, 5인 대사/완료 표정 아트 10종과 placeholder/final 매니페스트 키, 편성실 캐릭터 프레임 전환.
**수정한 것**: 대사는 42ms 간격으로 나타나며 평서 대사는 캐릭터별 대사 전신으로 고정되고, 출력 완료 뒤에도 그대로 유지하며 ▼가 8px 왕복한다. 표정이 지정된 대사는 해당 표정으로 시작부터 완료 후까지 유지한다. 대사·표정 원본은 `contain` 변환으로 기본 전신과 같은 인물 크기에 맞췄다. 전환할 때마다 기본 스프라이트와 동일한 위치·표시 크기를 적용하며 캐릭터별 위치 보정값은 두지 않는다. 모션 감소 설정에서는 즉시 출력하고 세모도 정지시킨다.
**검증**: `npm run art` 본 아트 118/125, `npm run typecheck`, `npm test` 10개 파일·74개, `npm run build` 통과.

## D7 · 첫 편성실 반복 노크

**프롬프트**: 첫 편성실에 손님이 없는 동안 2초 뒤 노크하고, 이후 3초마다 반복한다.
**수정한 것**: 첫날 문을 열기 전 화면에서만 노크 타이머를 시작한다. 첫 재생은 2초 뒤이며 이후 3초 간격으로 반복하고, 문을 누르거나 화면 상태가 바뀌면 즉시 중단한다. 소생실과 동일한 원본 노크음을 재사용한다.
**추가 조정**: 문을 누르면 노크를 멈춘 뒤 기존 타이틀 문 열림 효과음을 낮은 볼륨(0.28)으로 한 번 재생한다.
**타이틀 음량 조정**: 새 게임 시작의 띵 효과음만 0.55에서 0.32로 낮추고 문소리는 기존 음량을 유지한다.

## D8 · 아트 V3 캐릭터 스탯·대사 자산 통합

**프롬프트**: `아트_V3/캐릭터스탯.xlsm`과 `아트_V3/대사집/LIVE_STOCK_대사자산.xlsx`의 캐릭터 정보와 대사를 게임 시스템 전반에 반영한다.

**화면 연결**: 편성실·생방송·사망·소생 화면이 상황별 대사, 변수 치환, 표정 전신과 글자 연출을 사용하며 편성실 계약서에는 V3 프로필과 정확한 스탯을 표시한다.
**검증**: `npm run art` 본 아트 169/176 및 표정 placeholder/final 각 45개, `npm run typecheck`, `npm test` 11개 파일·77개 테스트 통과. 최종 빌드 검증은 같은 작업에서 수행한다.

## D8 · 편성실 진열 판매·가격 흥정

**프롬프트**: 판매할 장비는 진열대에 먼저 한 점 올리고, 종류별 하루 한 번만 판매하며 가격 배율에 따른 구매 확률과 최대 3회 흥정을 구현한다.
**규칙**: 무기·방어구·기타 슬롯별로 날짜마다 판매 성공을 한 번만 허용한다. 가격 제안 뒤에는 용사 반응과 가격표만 바뀌고, 별도 판매 입력이 진열 상품 전체에 시드 RNG를 한 번만 소비한다. 성공하면 전부 제거하고 해당 슬롯을 잠그며 실패하면 전부 남긴다.
**밸런스**: 배율 0.5–2.0, 0.1 단위, 기준 구매 확률과 배율당 증감, 최소·최대 확률, 최대 시도 횟수를 `balance.shopSale`로 분리했다. 현재 기준 정가 확률은 70%이고 낮은 가격일수록 상승한다.
**화면**: 별도의 판매 대상 선택 없이 팝업에서 같은 가격 배율을 제안하면 용사가 먼저 반응하고 진열대 가격표가 갱신된다. 이후 판매 버튼으로 전부 성공/전부 실패를 판정한다. 성공한 진열대는 배경 없이 큰 붉은 `오늘 판매 완료` 글자만 남긴다.
**검증**: `npm run typecheck`, `npm test` 11개 파일·78개 테스트 통과. 1,000시드 헤드리스 판매 정책도 진열→제안 순서로 갱신했다.

## D8 · 계약 확인과 방송 시작 분리

**프롬프트**: 편성실 계약 버튼의 첫 클릭에는 계약서를 펼쳐 확인 문구를 보여 주고, 두 번째 클릭에서 계약을 확정한 뒤 버튼을 방송으로 전환한다.
**규칙**: `OFFICE/CONTRACT_ACCEPT`는 계약금 차감·영입·오늘의 출연자 선택까지만 수행하고 OFFICE에 머문다. 이후 `OFFICE/CONFIRM`에서만 LIVE를 시작한다.
**화면**: 첫 계약 클릭은 계약서 상단에 큰 붉은 `정말 계약하시겠습니까?`를 표시한다. 같은 계약 버튼을 다시 누르면 계약하며, 확정 직후 네 번째 버튼은 `방송`으로 바뀐다. 계약서를 접거나 인벤토리를 열면 미완료 확인 상태를 취소한다.
**검증**: `npm run typecheck`, `npm test` 11개 파일·78개 테스트, `npm run build` 통과. 계약 확정 뒤 OFFICE 유지와 별도 방송 입력의 LIVE 전환을 테스트로 확인했다.

## D8 · 편성실 배경 TV

## D8 · 대사집 미연결 상황 연결

**연결**: `SHOP_ITEM`은 장비를 진열할 때, `SHOP_CONTRACT`는 계약 도장 완료 뒤, `SHOP_LEAVE`는 퇴장 전에 재생한다. `DUN_START`는 방송 진입 직후 무전 배너로, `REVIVE`는 소생 결제 완료 직후 소생실 대사창으로 연결했다.
**세부**: 퇴장 대사는 타자 연출이 끝난 뒤에만 실제 퇴장을 시작해 문/TV 흐름을 끊지 않는다. 장비 대사는 장비 이름과 유물 여부·무기 보유 상태를 조건/치환 문맥으로 전달한다.
**검증**: `npm.cmd run typecheck`, `npm.cmd run build` 통과. `npm.cmd test`는 기존 밸런스·승계 변경과 관련된 5개 실패(경제 3, roster 2)가 남아 있으며, 이번 대사 연결 변경으로 인한 타입 오류는 없다.

## D8 · 소생실 판매 장비 승계 드랍

**프롬프트**: 1사이클 후 소생실에서 시체를 수색할 때, 앞서 판매한 장비가 높은 확률로 다시 나오고 더 강한 승계 장비가 되게 한다.
**규칙**: 방송 중 판매된 장비는 사망 시 시체의 회수 목록에 남는다. 첫 방송이 끝난 뒤인 Day 2 소생실부터 해당 판매 장비마다 90% 확률로 강화된 `*_inherited` 복사본이 추가된다. 복사본은 기존 `REVIVE/LOOT`로 회수하며, 원본보다 높은 전투 스탯을 가진 독립 아이템 ID라 수량 기반 인벤토리 계약을 바꾸지 않는다.
**밸런스**: 발동일과 확률은 `balance.inheritanceLoot`에, 승계 장비의 HP/ATK/DEF/가격은 `items.json`에 둔다. 강화 장비는 기존 장비 슬롯을 그대로 사용한다.
**검증**: `npm.cmd run typecheck` 통과. 100개 시드에서 단검 승계본이 80회 이상 드랍되고 RNG 커서가 장비당 한 번만 소비되는지, 첫 사이클에는 미발동인지, 소생실 회수 액션이 승계본을 인벤토리로 옮기는지 `economy.spec.ts`로 검증했다. 전체 테스트는 기존 소생비 기준표 3건·로스터 승계 2건 실패로 81/86 통과했다.

## D8 · 시체 일반 장비 수색 풀

**프롬프트**: 승계 장비 외에도 시체에서 여러 장비 아이템이 나오게 한다.
**규칙**: 첫 방송이 끝난 뒤인 Day 2 소생실부터 시체마다 85% 확률로 일반 장비 1~2점이 추가된다. 일반 드랍은 승계본을 제외한 전체 GEAR 풀에서 중복 없이 뽑히며, 판매 이력 기반 승계본과 함께 기존 `REVIVE/LOOT`로 회수한다.
**밸런스**: 발동일·확률·수량 범위는 `balance.corpseGearLoot`에 분리했다.
**검증**: `npm.cmd run typecheck` 통과. 100개 시드에서 수색 성공 70회 이상, 1~2점 수량 범위, 동일 시체 내 중복 없음, 최소 8종 이상의 장비 다양성, 승계본 미포함을 `economy.spec.ts`로 확인했다. 소생비 기준표 3건의 기존 실패는 유지된다.

## D8 · 신문 일차별 방문 용사 후보

**규칙**: 방문 후보는 날짜에 따라 누적 해금한다. Day 1은 미레·루엔·비오레, Day 2는 메르네를 추가한 4명, Day 3부터는 세이로까지 포함한 5명이다.
**호환**: 루엔·세이로는 시작 소속 용사이기도 하므로 후보 풀에 같은 ID를 유지하되, 계약 수락 시 기존 Star를 재사용해 중복 몸을 생성하지 않는다.
**검증**: 120개 시드로 Day 1~3의 실제 방문자 ID 집합을 전수 검증하는 office 테스트를 추가했다. `npm.cmd run typecheck` 및 office 테스트 11건은 통과했다. 전체 테스트의 기존 실패는 소생비 밸런스 3건과 승계 데이터 2건이다.
