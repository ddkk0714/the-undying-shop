# Codex 활용 기록

## 우리의 방법론 — 문서 → 모듈 → 검증 루프

우리는 화면과 게임 규칙을 분리하고, 먼저 모듈 문서·공유 타입·수용 기준을 확정했다. Codex는 Phaser를 모르는 순수 TypeScript 코어와 콘텐츠 데이터만 담당했고, Claude Code는 그 상태를 읽어 화면을 만들었다. 모든 규칙 변경은 시드 RNG와 헤드리스 시뮬레이터로 재현했으며, 화면에서 발견된 문제도 테스트로 고정한 뒤 수정했다. 이는 AI에게 구현을 일괄 위임한 방식이 아니라, 사람이 모듈·소유권·검증 경계를 설계한 분업 구조다.

## D0 · 콘텐츠 계약

**프롬프트**: M03/M05/M06/M07/M10/M11 명세를 실행 가능한 JSON 데이터로 옮긴다.
**산출**: 밸런스, 아이템 12종, 스타 5명, 페르소나, 갈림길, 무전·채팅·서사 콘텐츠.
**수정한 것**: 표의 수치·수량·UTF-8을 먼저 검증해 코어와 화면이 같은 데이터를 읽게 했다.
**배운 것**: 데이터 계약을 먼저 고정하면 규칙과 UI가 서로 다른 수치를 해석하는 문제를 막을 수 있다.

## D1 · M02 상태머신과 M03/M04/M05 로스터·경제

**프롬프트**: 동결된 계약 위에 8일 상태머신, 소생·폐기, 계약 방문자, 페르소나 승계를 구현한다.
**산출**: 순수 reducer/store/RNG/sim, 소생 견적, 유품, 계약 수락·거절, 진열·물약·초기 재고.
**수정한 것**: 시체·몸·페르소나를 분리하고, 계약 지원자는 수락 뒤에만 출연·승계할 수 있게 했다. 골드 부족·지원자 고갈의 조기 종료 안전망도 추가했다.
**배운 것**: 계약 파일 변경은 CCR로 분리하고, 시체·정산처럼 여러 경로가 만나는 규칙은 하나의 멱등 함수로 합쳐야 이중 지급을 피할 수 있다.

## D2 · M06 하강·전투·무전

**프롬프트**: 3층 주기 전투, 시드 갈림길, 목격, 강제 사망을 화면 없이 완결한다.
**산출**: 장비 기반 HP/ATK/DEF 전투, 공격·방어·어필, 지체 페널티, 18/23/28F 목격, 거짓말 콜백.
**수정한 것**: 같은 시드에서는 같은 갈림길 결과가 나고 좌우 표시는 시드에 따라 바뀌게 했다. 사망 시 Corpse·팬·골드·최고층을 한 번만 정산하며 전투 대사와 하강 한계 사인도 한국어로 통일했다.
**배운 것**: RNG를 함수 내부의 숨은 난수가 아니라 입력·cursor 소비로 만들면 확률 규칙도 테스트 가능한 결정론이 된다.

## D3 · M08/M09/M11 정산·검시·엔딩

**프롬프트**: 죽음 뒤의 4가지 발표 조합과 기록·엔딩 규칙을 상태 전이로 증명한다.
**산출**: 얕은 사망 팬 손실, 일일 수입 원장, 검시 훼손 유품, HIDDEN 전이, A/B 엔딩 판정.
**수정한 것**: 온전한 시체를 실패로 공표하면 스타가 캐스팅에서 빠지고, 훼손하면 목격 기록이 억제되도록 분리했다.
**배운 것**: ‘진실’과 ‘발표’를 별도 상태로 저장해야 거짓 공표의 비용을 정확히 표현할 수 있다.

## D4 · M07 채팅·슈퍼챗과 M03 열화

**프롬프트**: 시청자 반응을 실제 방송 상황과 연결하고, 되살아난 몸의 후유증을 반영한다.
**산출**: leak·삭제 역풍·payPool, 상황별 채팅/슈퍼챗, 방송 시청자·채팅 속도 모델, 열화·승계 규칙.
**수정한 것**: 초반은 조용하고 깊이·위험·어필·슈퍼챗에 따라 시청자와 채팅 밀도가 변한다. 슈퍼챗은 감정·대사 payload를 전달하며, 진실 채팅은 과잉 삭제해도 사라지지 않는다.
**배운 것**: 화면 효과가 필요한 규칙도 core에서는 작은 의미 신호(payload)만 만들면 렌더러와 충돌하지 않는다.

## D5 · M10 슈퍼챗 중심 경제 검증

**프롬프트**: 현실적인 수입 구조를 시뮬레이션으로 검증하고, 무리한 밸런스 변경은 되돌린다.
**산출**: 보수·적극 계약, 저어필·항상어필, 훼손 회복 정책과 1,000시드 검증.
**수정한 것**: 슈퍼챗을 변동성 높은 주수입(약 61%), 굿즈를 안정 수입(약 36%), 재고/유품 판매를 비상 수단(약 4%)으로 확정했다. 목표에 맞지 않은 단일 노브 실험은 저장소에 남기지 않았다.
**배운 것**: 밸런스 목표와 자동 플레이 정책이 다르면 숫자를 억지로 맞추지 말고, 정책 자체가 어떤 플레이를 대표하는지 먼저 검증해야 한다.
